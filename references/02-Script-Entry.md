# 02 文案入口（clean 已实现 / original 未实现）

## 两个入口

| `script_mode` | 状态 | 输入 | 做什么 |
|---|---|---|---|
| `clean` | **已实现（第一期唯一路径）** | 完整原稿 / 来稿 | 断句、去口水、口播化、补 CTA、统一人名书名 |
| `merge`（整合改写，**默认入口**） | 已实现 | 1–N 篇同书文案（用户直接贴） | 去平台噪音/去重/按分数保留/补 CTA → 一条可配音的口播稿 |
| `original`（从零原创） | 未实现（接口名保留，不假装支持） | 只要主书 | 需要原创选题与结构；能力在 `booklist-pipeline`，本 Skill 不搬 |

用户要给 `original`，直接说：本 Skill 第一期只做来稿清洗，原创选题请走 `booklist-pipeline` 出稿，再回来跑 `clean`。

## merge 的判断标准（用户贴 1–N 篇时的主路径）

```bash
python3 <skill>/ours/rewrite_script.py --book "被讨厌的勇气" --sources a.txt b.txt --target-seconds 75
python3 <skill>/ours/rewrite_script.py --book "被讨厌的勇气" --source-dir sources --brief   # 给模型看的改写清单
```

- 平台噪音（关注/点赞/橱窗/下期/话题/栏目标记）**整句丢弃**（不是句内删字，句内删会把半句粘到下一句上）；CTA 统一在结尾生成。
- 重复句：归一化后 12 字前缀相同或字符 bigram 相似度 ≥0.82 → 丢。
- 保留优先级：书内观点/引文 > 数字年份 > 方法步骤（第一二第三步）> 场景故事；纯情绪句降权。
- 字数 = 目标秒数 × 4.2 字/秒；超出预算的按最低分丢，被丢的写进 `02-rewrite-record.md`。
- **不新增原稿没有的数字与页码**。
- 想要更好的文字：主 Agent 按 `--brief` 的 constraints 自己改写（质量高于机械合并），写到 `02-final-script.md`，`run_all` 检测到文件就不再机械合并。

## clean 的判断标准（用户给的是「已经很好的成稿」时）

1. **一句一口气**：一句话 12–28 字，超过 28 字在自然停顿处断开（TTS 断句和字幕都按句走）。
2. **口播优先**：书面连接词（「综上所述」「基于此」）删掉；「该书」→「这本书」。
3. **不新增事实**：原稿没写的数字、页码、案例，一律不加（03 会查数字能否溯源）。
4. **CTA 必须在最后一句之内**：含橱窗/左下角/评论区任一可执行动作。
5. **正文与记录分离**：`02-final-script.md` 只有正文（能被 TTS 直接读），改了什么写 `02-rewrite-record.md`。

## 输出

```
02-final-script.md      # 纯正文，一段一句；markdown 标题会被 shot_plan 自动跳过
02-rewrite-record.md    # 改了什么、为什么、原句 → 新句
```

## 闸门（转 03）

- 正文里没有「XX 页」「XX%」这类未核验数字，或已在记录里注明来源。
- 最后一句含 CTA 且不是纯口号（要有可执行动作）。
- 字数 / 3.5 ≈ TTS 秒数；超过 10 分钟先拆成系列，不硬塞一片。
